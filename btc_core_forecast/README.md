# Прогнозная система возврата ядра BTC

Рабочий исследовательский пакет. Торговая готовность не подтверждена, проверенные кандидаты отклонены. Содержит код, исходную историю, результаты последовательных проверок и сведения о реально запущенном отдельном сборе новых подписанных данных.

Исторические результаты изложены в `STATUS_20261013.md`. Действующий отдельный контур выпускает подписанные распределения цены на 1/4/24 часа и автоматически считает ошибки после закрытия соответствующего периода. Это компонент неопределённости, а не допущенная к торговле полная система. Его неизменяемый источник: `btc-core-distribution-forward-20261013`, журнал: `btc-core-distribution-evidence-20261013`.

## Воспроизведение

Установленные версии зависимостей перечислены в `requirements.txt`. Из каталога пакета:

```bash
python -m unittest discover -s . -p 'test_*.py' -v
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python run_research.py --spot data/spot_2024_2026H1.json.gz --derivatives data/derivatives_2024_2026H1.json.gz --funding data/funding_2024_2026H1.json.gz --output replay
```

Кэши массивов и большинство промежуточных моделей исключены из пакета: команда пересоздаёт их из исходных данных. JSON результатов сохранены. Последние исследовательские модели с деривативами сохранены для воспроизводимости и не допущены к торговле. `joblib` следует загружать только для известных доверенных артефактов.

`last_historical_forecast.json` относится к старой исторической точке, не к текущему рынку. Данные нового сборщика и его исходники находятся по ссылкам в отчёте. Они сохраняют самостоятельную подписанную историю; исходники сборщика в этот пакет не дублируются.

## Состав

`forecast.py` — первый совместный исследовательский прогноз на 72 часа; `walkforward.py` — последовательная квартальная диагностика; `nonlinear.py` — нелинейный прогноз цены; `direct_utility.py` — прямой прогноз дополнительного количества BTC от ожидания; `episode_execution.py` — однократные покупки в отдельных эпизодах; `paired_ablation.py` — построчное сравнение вклада деривативов; `long_holding.py` — отдельная многонедельная диагностика.

`availability.py` проверяет допустимость времени и версии факторов. Он не проверяет подписи и пока не делает макро численным входом модели. Для подписей сборщик использует отдельный опубликованный модуль; его реальная проверка приведена в JSON отчётах.

`protocol.json` — условия исследования полной системы; их выполнение не заявлено. Отдельные регистрации контуров сбора, прогнозного компонента и минутной проверки рынка не являются регистрацией готовой торговой модели.

## Единый кандидат и действующий контур

`joint_candidate.py` связывает цену, направление, порядок достижения −2%/+5% и отложенный вход одной совместной выборкой траекторий. Число соседей 256 и масса локальной части 50% зафиксированы. `joint_results`, `joint_macro_results`, `joint_objective_results` сохраняют отрицательные проверки; `runtime/joint_candidate_admission.json` фиксирует отклонение. Проверенная ранее история не объявляется независимым подтверждением.

`add_macro_context.py` сохраняет происхождение и ограничения исторических макроданных. Широкий индекс доллара не выдаётся за DXY, наличный NASDAQ100 — за фьючерс. Даты первой публикации исторических чисел не подтверждены; такие факторы не допущены в рабочий прогноз.

`candidate_contract.py` выдаёт единые исследовательские результаты и перечисляет конкретные причины блокировки торгового решения. Наличие входных данных не заменяет проверки их прогнозного вклада. `r6_factor_adapter.py` принимает только два явно зарегистрированных подписанта и временные границы их эпох, пересчитывает исходные факторы и проверяет неизменность формулы R6.

`impulse_check.py` проверяет свежие закрытые минутные свечи, изменение и внутрипериодный размах. Это распознавание уже случившегося движения, а не его предсказание. Действующий источник: `btc-core-live-quality-20261013`. При отсутствии свежих данных состояние спокойного рынка не создаётся.

`prospective_audit.py` независимо пересчитывает ошибки подписанного прогноза из опубликованных исходных свечей, проверяет связь прогноза с исходом и время подписания до исхода. Один исход не подтверждает прогнозную полезность. Текущее состояние внешних контуров и пределы доказательств перечислены в `runtime/ACTIVE_EXECUTION.json`.

`supervised_direction.py` — зафиксированная замена отвергнутой локальной модели: прямое обучение знака изменения на 1/4/24 часа с коррекцией на предшествующем калибровочном периоде и изменением весов целых траекторий. `supervised_direction_results/diagnostic.json` содержит одинаковые отрезки и дополнительные ориентиры 50/50 и предшествующую частоту роста. В июле часовая оценка хуже обоих ориентиров с отрицательным доверительным интервалом; `runtime/supervised_direction_admission.json` сохраняет отказ в допуске. Эта модель не установлена вместо действующего замороженного прогнозного компонента.

## Подключение R6 и макро до обучения

`factor_integration.py` собирает 38 численных входов из проверенных закрытых свечей, семи исходных факторов замороженной формулы R6, DXY, Nasdaq futures, исходной котировки индекса ^TNX с возрастом и режимом предыдущей сессии, а также счётчиков полученного официального календаря BLS. Котировка ^TNX не переименовывается в подтверждённую текущую доходность Treasury. Календарь BLS не объявляется полным макрокалендарём.

`macro_quote_adapter.py` проверяет подпись старых записей, символы, точные исходные HTTP-ответы, совпадение чисел и доступность до выбранного момента. Старый workflow подписывал записи, но загружал код сборщика из изменяемой ветки: этот недостаток не скрыт в пригодности к обучению. Новый источник `btc-core-macro-source-20261013`, коммит `08987b0fbfeb5ea1aa6b1c3fd287fea0b676ee21`, загружает код строго по `github.sha`. Его регистрация до начала сетки и настоящий preflight с тремя котировками и официальным календарём проверены; `runtime/pinned_macro_source_verification.json` содержит результат. Новый источник собирает данные, а не подтверждённые торговые прогнозы.

`integrated_dataset.py` добавляет только наступившие исходы. Неизвестные 24-часовые исходы остаются отсутствующими. Отложенные спотовые цены не выдаются за реальные сделки оператора. `integrated_candidate.py` фиксирует единственного кандидата R6_MACRO_SIGN_PATH_V1 и отказывается обучать его на отсутствующих факторах, незакреплённом макроисточнике, незакрытых траекториях или пересекающихся периодах обучения и калибровки.

`candidate_contract.py` проверяет зависимости и возраст источников до вызова прогнозного метода. Старые проверенные входы нельзя повторно использовать как свежий рынок; отсутствие реальных условий оператора блокирует расчёт входа. `runtime/frozen_integrated_candidate_spec.json` фиксирует входы и правила сравнения. Спецификация и исполняемый код не являются обученной моделью: текущий кандидат не обучен, торговый допуск отсутствует, общая задача не завершена.
